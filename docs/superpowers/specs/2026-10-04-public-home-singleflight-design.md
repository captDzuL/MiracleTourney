## Bounded scope and semantics

Change only `src/lib/events/public-home-read.ts` and its covering tests/RCA. A small dedicated helper/test file is allowed only if needed to keep one responsibility; do not create a general caching framework. Preserve reader name/return type and optional explicit `now` call compatibility. Existing full reader, homepage UI, pressure runner/workflow, Prisma/schema/dependencies and environment configuration stay unchanged.

Use a process-local map keyed by exact slug for the authoritative Ongoing transaction only. Read flags for each invocation before joining. Default-time calls may share. Explicit Date calls bypass sharing to retain deterministic per-call time semantics. Separate slugs never share. Query itself must still filter Ongoing, validate graph parent/nested structure, apply bounds and read only the exact published schedule in RepeatableRead. All query arguments/order/count/options remain unchanged.

Maximum tracked in-flight keys64; do not retain a slug longer than200characters in the map. At capacity or for oversized keys, run the unchanged independent path (no eviction, wait queue or error fabricated by the limiter). These are sharing bounds, not new input rejection. Keep both success/null and failure cleanup immediate on settlement; delete only the entry belonging to that operation. Never retain settled promises/results. No detached rejecting finally promise/unhandled rejection, and no test-only cache reset API in production.

Share only the ongoing transaction promise/result, not full-reader fallback. A null result (private/missing/non-Ongoing/invalid graph/overflow) falls back independently for every caller, exactly as before. Flags-off calls do not join a live authoritative operation. Private/missing at the shared transaction's captured snapshot never yields a public ongoing view. Overlapping callers knowingly share the leader snapshot, including changes made while that snapshot is in flight; calls after settlement re-read publication/status/matches and must not reuse that snapshot. Do not promise linearizable visibility or cross-process coalescing.

Return isolated plain-data view objects for successful shared public results (for example structuredClone per consumer), so one caller cannot mutate another caller's result. Rejected operations propagate the original error identity to all waiters; no retry/fallback-on-rejection, fabricated content or success conversion. Preserve safe trace semantics: only an actual transaction leader emits transaction-start/entry; joiners must not be reported as having executed transactions. Existing trace error classes and privacy remain unchanged; add no raw slug/ID/error details or new diagnostic subsystem.
